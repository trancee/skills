# Tutorial rules

Source: [Tutorials](https://diataxis.fr/tutorials/), [tutorial vs how-to](https://diataxis.fr/tutorials-how-to/).
Mode=action+acquisition. Tutor owns learner success. Difficulty irrelevant.

## Contract

- start: concrete destination/build, not "learn X"
- controlled safe repeatable setting; one path; required prerequisites fixed
- every step: action -> visible meaningful result -> exact expected observation
- early/frequent results; flag likely mismatch and recovery
- prompt notice of output/file/prompt/state changes
- concrete before abstract; useful repetition possible
- explanation <= immediate clause + link
- options/alternatives/reference detail removed or linked
- end: successful useful whole, no gaps learner must infer
- human output: `we` + direct commands + natural English

## Shape

1. State artifact/outcome.
2. Set known start state.
3. For each step: command/action; expected result; observation.
4. Verify final artifact actually runs/works.
5. Give repeat/reset path if useful.

## Reject

- goal-oriented production problem => how-to
- paragraphs of background
- menus/branching choices
- "you will learn"
- result-free steps
- untested happy path
- abstraction/generalization replacing concrete action

DONE only after end-to-end run in documented environment produces every promised result.
