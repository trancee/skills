# Explanation rules

Source: [Explanation](https://diataxis.fr/explanation/), [reference vs explanation](https://diataxis.fr/reference-explanation/).
Mode=cognition+acquisition. Readable away from active task.

## Contract

- one bounded why/about question
- title tolerates implicit "About"/"Why"
- build mental model via context, reasons, history, constraints, implications, connections
- include useful alternatives, viewpoints, opinions, counterexamples, tradeoffs
- connect outside topic only when it clarifies governing question
- viewpoint wider than task/reference; facts remain grounded
- no step sequence; move to how-to
- no detailed machinery listing; move to reference
- human output: coherent natural English with explicit viewpoint

## Shape

1. State governing question/topic boundary.
2. Give context/problem history.
3. Explain design/reasons/connections.
4. Compare alternatives and implications.
5. Close on resulting mental model, not generic conclusion.

## Reject

unbounded survey; hidden procedure; API table; scattered explanation in tutorial/how-to; single perspective where alternatives matter; neutral pretense over actual judgment.
