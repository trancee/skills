# How-to rules

Source: [How-to guides](https://diataxis.fr/how-to-guides/), [tutorial vs how-to](https://diataxis.fr/tutorials-how-to/).
Mode=action+application. Competent practitioner owns judgment.

## Contract

- title = exact real goal/problem: "How to X"
- start/end at meaningful work boundaries; not forced lesson
- executable sequence from user goal, not tool feature list
- condition before action; common path first
- include only necessary judgment, branches, alternatives, risk, recovery
- logical flow; minimize tool/context switching and open concerns
- practical usability > option completeness
- no fundamentals teaching; no extended why; no exhaustive API tables
- sustained explanation/reference/tutorial => move+link
- human output: direct commands, second person, natural English

## Test

Representative practitioner+environment executes goal. Verify commands, branches, expected result, failure recovery.

## Reject

- broad domain ("build a web app")
- tool-topic title ("Settings panel")
- tutorial hand-holding/study path
- reference completeness
- exact-case-only recipe with no required real-world branches
- title not stating goal
